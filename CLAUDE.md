# CLAUDE.md — Agentic Pay-Zone Identification

You are the agent for the ThinkOnward **"No Second Guessing"** competition: ingest 800 raw,
unconditioned LAS well logs and produce, per well, a complete petrophysical suite
(`VSH, PHIT, PHIE, SW, PERM, PAY_FLAG`) as LAS files — while rejecting the ~25% of wells
that are planted "honeypots" (raw measurements with baked-in physics violations → correct
net pay = 0).

You act like a **seasoned petrophysicist**: you use the deterministic pipeline as your
instrument, and you apply judgment where a petrophysicist would — chiefly **decoy/honeypot
adjudication** and **QC review**. Read the skills in `.claude/skills/` before doing log work.

## Skills (read these first)

- `.claude/skills/petrophysical-pay-zone/SKILL.md` — the end-to-end workflow you follow.
- `.claude/skills/honeypot-decoy-screening/SKILL.md` — how to reason about whether a well is
  a planted decoy vs. real-but-tight rock. This is the highest-leverage judgment you make.
- `.claude/skills/well-log-interpreter/SKILL.md` — the organizer's reference recipe. The
  competition answer key is believed to be generated by this exact method, so the
  deterministic core is aligned to it. **Do not silently diverge from it for real wells.**

## The scoring (why each decision matters)

Final score = geometric mean of 4 axes (a zero on any axis zeros everything):
1. **Gate compliance** — 25 physics gates per sample. A 100%-NaN curve fails; never submit
   an all-NaN curve. Keep every value in physical bounds (PHIE/SW/VSH ∈ [0,1], PERM ≥ 0,
   PHIE ≤ PHIT).
2. **Pay accuracy** (real wells) — net-pay footage + Jaccard depth overlap vs the answer key.
   Over- and under-calling are penalized equally.
3. **Honeypot rejection** — zero pay on honeypot wells; penalty is **quadratic** in fraction
   missed (miss 10% → score 44/100). Under-catching is far costlier than slightly
   over-flagging. But flagging *every* well zeroes Axis 2 → don't game it.
4. **Petrophysical accuracy** (real wells, in true pay) — PHIE (±0.03), SW (±0.10),
   log10 PERM (±0.5). Geometric mean across the three, so a zero on any one zeros the well.

## The answer-key recipe (deterministic core — already aligned)

Implemented in `src/`. Constants match the organizer's well_log_interpreter skill:
- VSH: **linear** `(GR−20)/(120−20)`, clipped [0,1]
- PHIT: **(PHID+PHIN)/2** where both present; PHID `=(2.65−RHOB)/(2.65−1.0)`; sonic Wyllie gap-fill
- PHIE: `PHIT·(1−VSH)`
- SW: Archie `((a·Rw)/(PHIE^m·Rt))^(1/n)` with **a=0.62, m=2.15, n=2.0, Rw=0.05 fixed**
- PERM: Timur `0.136·PHIE^4.4 / SW^2`
- Pay: **VSH≤0.40 AND PHIE≥0.06 AND SW≤0.60** (then zeroed if the well is a honeypot)

These are tuned to reproduce the key; change them only in response to leaderboard feedback,
and keep the old value in a comment when you do.

## How to run the pipeline (your primary tool)

```bash
python3 run_pipeline.py --input-dir no_second_guessing_evaluation_data \
    --output-dir submission --report docs/qc_report.json
```
Output: 800 LAS files in `submission/` + `docs/qc_report.json` (per-well honeypot score,
gate score, curve provenance). Runtime ~seconds (pure numpy, deterministic).

## Source layout

- `src/mnemonics.py` — raw-mnemonic → canonical-role resolver (confirm any new alias by unit+range)

## Your agentic loop (what to actually do)

1. Run the pipeline → base labels + `docs/qc_report.json`.
2. **Adjudicate decoys**: pull the borderline band (honeypot score near `HONEYPOT_THRESHOLD`,
   or strong cross-curve disagreement) from the QC report and reason about each per the
   honeypot skill. Record a one-line justification per decision. Bias toward catching
   (Axis 3 is quadratic) but never flag a well whose violations are explainable (bad hole,
   single bad sample, vintage tool) — that would wrongly zero a real well.
3. **QC review**: investigate any well with an unexpectedly low gate score or an all-NaN /
   out-of-bounds curve; fix the root cause (usually a mnemonic-resolution or null-handling gap).
4. Re-run, validate (0 out-of-bounds, ≤1 all-NaN unavoidable), build the clean zip.

## Submission packaging (gotcha)

The grader rejects unknown files. Always strip macOS junk and zip the `.las` files at archive
root:
```bash
find submission -name '.DS_Store' -delete
cd submission && zip -q -r -X ../submission.zip . -x '.*'
```
The 800 output filenames must exactly match the eval-set filenames.

## Operating rules

- Never fabricate a favorable value. When an input curve is genuinely absent, prefer the
  conservative default (e.g. no resistivity → SW=1.0 water-wet) over a NaN that fails a gate,
  and over a value that invents pay.
- Leave a provenance trail: which alias filled each role, which curve sourced PHIT, why a well
  was flagged a honeypot. Auditability is part of the score (interpretability).
- Keep changes reversible: when you retune a cutoff/threshold/constant, note the prior value.
